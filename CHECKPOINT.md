# AetherCore S1.2 checkpoint

## Status

S1.2 freezes a real compiler-produced RV64IM software corpus before any further CPU microarchitecture change. The core remains the verified five-stage in-order RV64IM implementation from S1/S1.1; no CPU RTL changed in this checkpoint.

The software path is:

```text
freestanding C
  -> riscv64-unknown-elf-gcc
  -> crt0.S + linker.ld
  -> ELF + flat binary + map + disassembly
  -> Verilated AetherCore
  -> one NEMU step per normal DUT retirement
```

## Core baseline

- IF/ID/EX/MEM/WB five-stage in-order pipeline.
- Complete RV64I and all thirteen RV64M register instructions.
- EX/MEM and MEM/WB forwarding, load-use interlock and branch recovery.
- Forwarded EX operands preserved across memory backpressure.
- Host-backed 64 MiB RAM, UART MMIO at `0x10000000`, exit MMIO at `0x10000008`.
- Architectural commit trace and precise suppression of younger memory side effects at fault retirement.
- Pinned OpenXiangShan/NEMU commit-level DiffTest.

The multiply/divide implementation is still combinational and correctness-first. It is not the final FPGA implementation.

## S1.2 real-program expansion

New source workloads:

- `sort`: insertion sort and recursive quicksort over signed 64-bit values;
- `crc_hash`: generated bytes, bitwise CRC32, FNV-1a and rotate/multiply hashing;
- `mixed_integer`: signed 7x7 matrix multiplication and signed quotient/remainder chains.

Each new source is compiled independently at `-O0`, `-O2` and `-Os`. The original S1.1 `call_stack`, `memory` and `arithmetic` binaries remain unchanged.

Host-side Python references independently recompute the CRC/hash and matrix/division constants before target execution.

## Compiler-neutral corpus contract

The manifest format is:

```text
name source optimization stall words bytes sha256
```

The runner does not depend on GCC-specific metadata. A future Minic producer can emit the same manifest and reuse the identical Verilator/NEMU execution path.

Two distinct gates must remain separate:

1. **Frozen-binary microarchitecture gate:** run the exact recorded binary hashes unchanged.
2. **Compiler compatibility gate:** rebuild the same C sources with GCC or Minic, then record and verify the new artifacts.

A CPU change may not silently recompile the corpus to obtain a passing result.

## Known limitations

- Multiply/divide remains combinational and unsuitable for final FPGA timing/area.
- The linker emits a non-fatal RWX LOAD-segment warning; later cleanup should split text and data program headers.
- Minic has not yet produced this corpus in the MiniCore repository.
- Privileged CSRs, trap redirection, interrupts, Sv39 and caches are not implemented.
- Precise faults still halt instead of entering an architectural trap handler.

## Next gate

2. compile the same sources with GCC and Minic and compare program-visible results;
3. retain both compilers' ELF, binary, map and disassembly evidence;
4. define a multi-cycle M-unit `req/busy/resp` contract;
5. replace combinational division test-first;
6. run the exact frozen GCC hashes plus the Minic corpus without recompilation.

Only after the real-program corpus survives the multi-cycle execution change should development enter privileged architecture.
