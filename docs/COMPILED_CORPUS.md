# Frozen compiler-produced RV64IM corpus

This corpus is the software compatibility gate for AetherCore microarchitectural changes. Every image is built from repository-owned freestanding C, `crt0.S` and `linker.ld`, then executed by the Verilated RTL while each normal retirement is compared one-for-one against the pinned NEMU reference.

Reference run: GitHub Actions `30702481540`.

Toolchain:

```text
riscv64-unknown-elf-gcc 13.2.0
binutils-riscv64-unknown-elf 2.42
-march=rv64im -mabi=lp64 -mcmodel=medany -mno-relax
-ffreestanding -fno-builtin -nostdlib -nostartfiles -static
```

## Workload intent

- `call_stack`: recursion, nested calls, stack frames, structures and remainder.
- `memory`: byte loops, pointers, global data, structures and deterministic backpressure.
- `arithmetic`: signed/unsigned RV64M and W-class dependency chains.
- `sort`: insertion sort plus recursive quicksort over signed 64-bit values.
- `crc_hash`: generated byte stream, bitwise CRC32, FNV-1a and rotate/multiply hashing.
- `mixed_integer`: signed 7x7 matrix multiplication and signed quotient/remainder chains.

The `-O0`, `-O2` and `-Os` variants are intentionally retained independently. They expose different stack layouts, register allocation, branch shapes, instruction counts and memory schedules while computing the same source-level result.

## Compatibility rule

Future execution-unit, pipeline, cache and bus changes must run these exact binary hashes unchanged. Recompiling the corpus is a separate compiler-compatibility operation and must not replace the frozen-binary microarchitecture gate.

The manifest format is compiler-neutral (`name source optimization stall words bytes sha256`). A Minic producer should emit the same format so GCC and Minic outputs can use the same Verilator/NEMU runner.
